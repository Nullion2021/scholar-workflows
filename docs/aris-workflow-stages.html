ARIS 工作流阶段详解

按各个编排技能的 SKILL.md 展开：每阶段读什么、依次做什么、产出什么、什么情况继续或停下。点击技能名称可打开克隆仓库中的原文件。

源码快照 3b19a22主线 W1 → W1.5 → W2 → W3本页是流程说明，不是运行记录

总流程与默认行为

/research-pipeline 串起四段主流程，并将参数与阶段产物传给下一段。它先做 W1、W1.5、W2，然后整理 NARRATIVE_REPORT.md；AUTO_WRITE=false 是默认值，因此 W3 论文写作通常需要另行启动或显式打开。运行状态保存在 .aris/runs/<run_id>.json，阶段有“产物写完”和“通过验收”两种不同状态。

W1 找题与方案方向 → idea 与实验计划W1.5 实验桥接计划 → 代码与初始结果W2 评审循环结果 → 修复与可支撑主张W3 论文写作叙事 → 论文与审计
阅读边界：下面描述的是仓库要求代理执行的工作流。模型评审、脚本校验和人工科学判断负责不同问题；某个阶段写了“完成”并不能单独证明论文或研究结论可靠。

W1 · 找题与方案

/idea-discovery：从宽泛研究方向形成推荐 idea 和下一步实验路线。

输入

研究方向；可选 RESEARCH_BRIEF.md、参考论文、已有结果，以及时间、数据、算力和 venue 约束。

核心产物

idea-stage/IDEA_REPORT.md、refine-logs/FINAL_PROPOSAL.md、refine-logs/EXPERIMENT_PLAN.md 与 tracker。

  1. 载入边界与参考论文

    先读研究简报；有参考论文时提炼方法、结果、局限与可能延伸。没有简报则从用户输入确定方向。

  2. research-lit：画文献地形图

    汇集个人文献库、本地 PDF 与外部检索，归纳子方向、已有方法、分歧和待验证问题。未指定 sources: 时，W1 传入 all, gemini；不可用来源按规则跳过。

  3. idea-creator：发散、初筛与 pilot

    提出候选假设，记录最小实验、贡献、风险和成本；合并重复项，对优选想法做低成本 pilot。阶段结果折入同一份 IDEA_REPORT.md。

  4. novelty-check：逐项查新

    对优选想法检索最接近的已有工作，比较核心主张和可核对的差异；已有论文确实覆盖的想法从候选中剔除。

  5. research-review：外部批判

    请外部 reviewer 指出最强支持理由、主要风险和最便宜的区分性实验，把评审结论写回报告。

  6. research-refine-pipeline：方法精炼与实验规划

    先以 research-refine 固定问题锚点与方法主张，再由 experiment-plan 排出与主张对应的实验、消融、预算和顺序。

  7. 汇总与交接

    在 IDEA_REPORT.md 保留排名、查新、pilot、评审和淘汰理由；有推荐想法时另写 idea-stage/docs/research_contract.md，让下一阶段只读取已选主张与最低证据要求。

继续条件AUTO_PROCEED=true 时各选择点报告自动选择并继续；设为 false 才等待研究者选择。阶段证据 gate 缺失时报告 BLOCKED，不能仅靠勾选步骤声称完成。

建议先看：IDEA_REPORT.md 的候选与淘汰理由、research_contract.md 的核心主张，以及 EXPERIMENT_PLAN.md 是否真的能检验主张。

依据：idea-discovery/SKILL.md 的 Phase 0–5.6。

W1.5 · 实验桥接

/experiment-bridge：把纸面实验计划落成可执行任务并收集第一批结果。

输入

refine-logs/EXPERIMENT_PLAN.md 为首选；还可读 tracker、最终方案、研究契约和 W1 报告。

核心产物

实验脚本、初始结果、refine-logs/EXPERIMENT_RESULTS.md 与更新后的 EXPERIMENT_TRACKER.md。

  1. 拆计划

    读出 sanity、baseline、主方法和消融的运行顺序，以及数据集、指标、seed、成功标准和预计 GPU 小时。

  2. 实现并审查代码

    复用已有代码，补训练和评估脚本、日志及机器可读结果。默认开启跨模型代码审查，重点查方法实现、数据划分、指标和 ground truth。

  3. 先跑最小 sanity 实验

    确认训练循环、指标、显存和输出格式。失败时最多尝试两次局部修补和两次干净重做；仍失败就停下并报告错误及尝试。

  4. 按里程碑部署与监控

    小批任务交给 run-experiment；大量多 seed、多配置或存在阶段依赖时转向 experiment-queue。用 monitor-experiment 跟踪。

  5. 收结果并判断后续实验

    把 JSON/CSV 和日志汇入 tracker，对照预先写好的成功标准；若主结果为正，可调用 ablation-planner 补消融计划。

继续条件默认 AUTO_DEPLOY=true，实现和审查后会部署；设为 false 才在部署前停下。Sanity 未通过或必跑实验未产出可信结果时，不应把该阶段当成“已准备好进入 W2”。

建议先看：实验计划与真实运行配置是否一致；结果文件能否复算报告中的指标。

依据：experiment-bridge/SKILL.md 的 Phase 1–6。

W2 · 评审与修复循环

/auto-review-loop：让外部评审指出弱点，修复后带着新证据再次评审。

输入

当前论文或研究叙事、实验结果、历史评审与待解决问题；中断时读 review-stage/REVIEW_STATE.json。

核心产物

review-stage/AUTO_REVIEW.md、REVIEW_STATE.json，以及有条件产生的 CLAIMS_FROM_RESULTS.md。

  1. 初始化或恢复

    读取当前研究材料、结果和已有评审；若状态文件显示近期未完成运行，则从下一轮恢复，而非从头开始。

  2. 外部评审

    按当前平台与配置选择 reviewer，得到原始评分、ready / almost / not ready 判定及具体批评；保留 reviewer 原文和追踪记录。

  3. 独立停止判定

    用 review_gate.py 判定当前评审是否足够：默认需分数至少 6/10，且 verdict 为 ready 或 almost，两项同时成立。不同评审后端还有各自的身份与最终裁决规则。

  4. 未通过则修复

    按严重度改代码、补分析、补可负担的实验或校正研究叙事；若启动实验，等真实结果回来再进入下一轮评审。

  5. 记录每轮与交接

    把原始评审、改动和结果追加到 AUTO_REVIEW.md，保存可恢复状态。结束时尝试用 result-to-claim 判断结果实际支持哪些论文主张。

继续条件默认最多 4 轮。到上限也会结束，但若没有获得符合规则的积极评审，必须列出剩余阻碍；这与“已通过”是两种状态。HUMAN_CHECKPOINT=true 时每轮评审后可由研究者决定修复方向。

建议先看：原始 reviewer 意见、实际修改后的证据，以及最终停止原因；单看分数轨迹不足以判断研究是否成熟。

依据：auto-review-loop/SKILL.md 的初始化、循环、停止 gate 与终止段。

W3 · 论文写作与审计

/paper-writing：把研究叙事变为可编译论文，并按 assurance 等级运行证据检查。

输入

NARRATIVE_REPORT.md、图表和结果文件、目标 venue；可选写作风格参考。必须有真实研究内容。

核心产物

paper/main.tex、章节、参考文献、图表、paper/main.pdf 和各审计报告。

  1. 设定 assurance 与论文契约

    默认 draft；max / beast 推导为 submission。先用 paper-plan 建大纲、主张证据矩阵和图表计划，并在写作前记录验收条件。

  2. 制作图表和方法示意

    paper-figure 从数据生成图表。架构示意可按配置选 figure-spec（默认）、Gemini 插图、Codex 图像、Mermaid，或手工提供。

  3. 逐节写作并编译

    paper-write 生成 LaTeX 章节和引文；paper-compile 构建 PDF 并检查引用、页数和排版。

  4. 内容修订

    auto-paper-improvement-loop 默认进行两轮评审、修订和重编译。理论论文可先经 proof-checker 检查证明。

  5. 核对主张与来源

    有数值主张和原始结果时，最终重跑 paper-claim-audit；有引文时运行 citation-audit。理论或范围较强的论文还可能调用 kill-argument。投稿级别默认包含 integrity-forensics。

  6. 投稿 gate 与最终报告

    assurance: submission 时，相关审计必须留下 JSON 结果，由 verify_paper_audits.sh 核对存在性、格式、新鲜度与阻断 verdict；论文验收契约和取证 gate 另行检查。任何红灯都会阻止最终报告。

继续条件draft 与 submission 的门槛不同；编译成功仅表示 PDF 生成。投稿级最终报告还要过审计 gate，并区分独立接受与暂定状态。

建议先看：论文中的每个核心主张能否指向结果或文献；各审计是否针对最终版本而非旧稿运行。

依据：paper-writing/SKILL.md 的 Phase 0–6。

W4–W6 · 论文之后按需启动

这三条不是 W1–W3 的固定后续：只有收到审稿意见、准备改投或准备报告时才选对应入口。

W4 · rebuttal

输入论文与审稿意见，输出可提交的回复。

  1. 校验 venue 规则并把意见拆成独立问题。
  2. 为每条问题定证据和回复策略；必要时补有限实验。
  3. 起草、做安全校验、交外部 reviewer 压力测试。

重点检查承诺是否有证据、是否覆盖每条评论。

W5 · resubmit-pipeline

输入旧论文与新 venue，输出隔离的新版本。

  1. 先复制隔离并做健康、匿名和审计检查。
  2. 在白名单内做针对性文本修改。
  3. 过对抗 gate、编译、审查差异和最终报告。

硬约束：不新增实验、不改参考文献、不覆盖旧投稿。

W6 · paper-talk

输入已编译论文，输出会议报告资料。

  1. 确认幻灯片大纲，调用 paper-slides 做 Beamer/PPTX。
  2. 按 assurance 水平用 slides-polish 逐页打磨。
  3. 核查幻灯片主张、引用与匿名信息，再导出。

另有独立 paper-poster-html 做海报。

独立支线与横向能力

专利与基金

patent-pipeline 从现有技术检索、可专利性判断、发明披露、权利要求、说明书，走到外部审查和法域格式。grant-proposal 则从研究想法和文献起草基金申请。

证明与领域变体

proof-orchestrator 管理跨 run 的证明任务；proof-writer 写证明，proof-checker 独立核验。idea-discovery-robot 是机器人找题适配版。

记忆与自我改进

research-wiki 跨阶段保存论文、想法、实验和主张。meta-optimize 只提出 skill 改进，meta-apply 才负责在通过门槛后应用。
